# 📊 Executive Report: eShopLegacyMVC Solution Upgrade to .NET 10  
  
## 1. 🧭 Executive Summary  
  
- 🎯 **Scope:** 3 projects in `eShopLegacyMVCSolution` moved from .NET Framework 4.6.1/4.7.2 (and ASP.NET Core 2.2 on net461) to **net10.0**:  
  - `eShopLegacy.Utilities` (class library)  
  - `eShopPorted` (ASP.NET Core web app)  
  - `src/eShopLegacyMVC` (ASP.NET MVC 5 + Web API 2 + EF6 web app)  
- ✅ **Outcome:** every project builds with **0 errors and 0 warnings** in Debug and Release. The `eShopLegacyMVC.sln` solution build is also clean.  
- 🔁 **How:**  
  - Microsoft Upgrade Assistant upgraded the two simpler projects.  
  - It crashed on `eShopLegacyMVC` because `Microsoft.WebApplication.targets` is not on Linux.  
  - Kiro CLI then did the full migration of `eShopLegacyMVC` by hand: System.Web, MVC 5, Web API 2 and EF6 moved to ASP.NET Core MVC and EF Core 10. It also fixed the leftover issues in the other two projects.  
- ⏱️ **Duration:** the run started at 13:47:50 UTC. The Kiro CLI session took about **9 minutes** (31.27 credits).  
- 📦 **Footprint:** 145 files changed (+250 / −1,424 lines). 96 of them are static assets that were moved (renames).  
- ⚠️ **Not verified at runtime:** the apps were not run against SQL Server, and the solution has no automated tests.  
  
## 2. 🏗️ Application Changes  
  
### 📚 eShopLegacy.Utilities  
- 🎯 Multi-targets `net10.0;netstandard2.0`, so .NET Framework callers can still use it.  
- 🔐 `BinaryFormatter` was replaced with `System.Text.Json`, because `BinaryFormatter` is removed in .NET 9+ and is insecure.  
  
### 🌐 eShopLegacyMVC (main legacy app)  
- 🧱 **Project file:** the classic `.csproj` with `packages.config` became an SDK-style `Microsoft.NET.Sdk.Web` project.  
- 🚀 **Startup:** `Global.asax` and `App_Start/*` (Bundle, Filter, Route and WebApi config) were replaced by a minimal-hosting `Program.cs`.  
- ⚙️ **Config:** `Web.config` and its transforms were replaced by `appsettings.json` and `appsettings.Development.json`.  
- 🗄️ **Data:** EF6 became EF Core 10 (SQL Server).  
- 🧩 **DI:** Autofac stays the container (MVC5/WebApi2 integration → `Autofac.Extensions.DependencyInjection`).  
- 🔌 **APIs:** Web API 2 `ApiController`s became ASP.NET Core `[ApiController]`s on the same routes.  
- 🎨 **Static files:** `Content`, `Scripts`, `fonts`, `Pics`, `Images` and `favicon.ico` moved to `wwwroot`. `Images` was renamed to `images` because Linux paths are case-sensitive.  
- 🧹 **Removed:** Application Insights (it had no key configured), the System.Web.Optimization bundles, `ApplicationInsights.config` and `Views/Web.config`.  
  
### 🔧 eShopPorted  
- 🏠 **Hosting:** the obsolete `WebHost`/`UseMvc` setup became the generic Host with endpoint routing. `ConfigureContainer` now registers the Autofac module.  
- 📦 **Packages:** the .NET Framework fallback packages (Autofac.Mvc5, WebGrease, Antlr, Microsoft.AspNet.*) are gone.  
- 🖼️ **Bug fix:** `PicController` was still on `System.Web.Mvc` and its picture path was empty. It now uses ASP.NET Core and reads from `wwwroot/Pics`.

## 4. 💻 Code Changes  
  
### 🗄️ Data access (EF6 → EF Core 10)  
- `CatalogDBContext`: `DbModelBuilder`/`EntityTypeConfiguration` became `ModelBuilder`/`EntityTypeBuilder`.  
- `HasRequired` became `HasOne().IsRequired()`, and the constructor now takes `DbContextOptions`.  
- EF6 key behaviour is kept:  
  - Brand and type Ids are identity columns, and client-set Ids are ignored.  
  - Item Ids use `ValueGeneratedNever` (they come from the HiLo sequence).  
  - Price is `HasPrecision(18,2)`.  
- `CatalogDBInitializer`: the `CreateDatabaseIfNotExists` + `Seed` pair became `InitializeDatabase()`, which calls `EnsureCreated()` and seeds only when it created the database.  
- `SqlQuery<long>` became `SqlQueryRaw<long>().AsEnumerable()`, and `ExecuteSqlCommand` became `ExecuteSqlRaw`.  
- `HostingEnvironment`/`ConfigurationManager` became `IWebHostEnvironment`/`IConfiguration`.  
- SQL script paths no longer use Windows backslashes.  
  
### 🚦 Startup and pipeline (`Program.cs`)  
- 🧩 Autofac via `AutofacServiceProviderFactory`, plus `AddDbContext`.  
- 🍪 `Session_Start` became session middleware (`AddSession`/`UseSession`) that sets `MachineName` and `SessionStartTime`.  
- 📝 `Application_BeginRequest` became middleware that sets the log4net `LogicalThreadContext` properties (`ActivityIdHelper` and `WebRequestInfo` moved to `LoggingContext.cs`).  
- 🌍 `<globalization en-US>` became `UseRequestLocalization`.  
- 🚨 `HandleErrorAttribute` became `UseExceptionHandler("/Error")` with a new `ErrorController`, outside Development only.  
  
### 🎮 Controllers  
- `System.Web.Mvc` → `Microsoft.AspNetCore.Mvc`:  
  - `HttpStatusCodeResult` → `BadRequest()`  
  - `HttpNotFound()` → `NotFound()`  
  - `Bind(Include=…)` → `Bind("…")`  
  - `Request.Url.Scheme` → `Request.Scheme`  
  - `Server.MapPath` → `WebRootPath`  
- Web API:  
  - `IHttpActionResult`/`HttpResponseMessage` → `IActionResult`/`File()`  
  - Routes are now attribute routes: `api/brands`, `api/brands/{id}`, `api/files`.  
  - JSON keeps PascalCase property names so the API contract does not change.  
- An unused `System.Runtime.Remoting.Messaging` import was removed.  
  
### 🖼️ Views  
- ➕ Added `_ViewImports.cshtml` (tag helpers and namespaces).  
- `@Scripts.Render`/`@Styles.Render` became `<environment>`-aware `<link>`/`<script>` tags: full files in Development, `.min` files with `asp-append-version` elsewhere.  
- `HttpContext.Current.Session[...]` became `Context.Session.GetString(...)`.  
- `Html.Partial` became `Html.PartialAsync`.  
- 🐛 `ActionLink(text, action, null, attrs)` now uses named arguments. In ASP.NET Core a `null` third argument binds to the `controllerName` overload and produces the wrong URL. Fixed in both web apps.  
  
### 📦 Packages and security  
- ⬆️ Autofac 9.3.4, Autofac.Extensions.DependencyInjection 11.0.2, log4net 3.5.0 (fixes GHSA-4f7c-pmjv-c25w) and EF Core 10.0.13.  
- 🛡️ Pinned `System.Security.Cryptography.Pkcs` 10.0.13. This fixes NU1902/NU1903 (GHSA-2fmv-rv2c-59x7, GHSA-846f-f764-76mx) on the version that Microsoft.Data.SqlClient pulled in.  
- 🧹 EF1003 (raw SQL built from strings) is suppressed with a written reason: the sequence names are private constants, not user input.  
- 🧹 The NU1510 and NU1701 package warnings are gone.

### ⚠️ Behaviour changes to review  
- 🔄 `api/files` now returns JSON, not BinaryFormatter bytes. Any consumer that reads the old format must change.  
- 🚀 The database initializer now runs at startup instead of on first use, so the app will not start if the database can't be reached.  
- 📡 Web API no longer offers XML responses (JSON only). `GET /api` now returns JSON, where MVC 5 used to block it.  
- 📉 Application Insights was removed. Re-add `Microsoft.ApplicationInsights.AspNetCore`/Azure Monitor with a connection string if you need telemetry.  
  
### 🚀 Improvements  
- 🧪 Add a test project (xUnit) for the services, the controllers and the `Serializing` round trip.  
- 🔐 Use per-environment connection strings via `ConnectionStrings__CatalogDBContext`. Microsoft.Data.SqlClient defaults to `Encrypt=True`, so servers other than localdb may need encryption settings.  
- 🗃️ Replace `EnsureCreated` with EF Core migrations.  
- 🖥️ Use a distributed cache for session state if you run more than one instance.  
- 📝 Consider moving from log4net to `Microsoft.Extensions.Logging`. Separately, `log4Net.xml` references `%property{activity}` while the code sets `activityid`; this mismatch existed before the upgrade.  
- 🐛 Fix the existing eShopPorted issues:  
  - `UseExceptionHandler("/Home/Error")` points to a controller that doesn't exist.  
  - `~/images` vs `wwwroot/Images` casing breaks on Linux.  
  - The EF Core 2.2 migrations should be regenerated.  
- 🐳 Containerize for Linux (`mcr.microsoft.com/dotnet/aspnet:10.0`, KB doc 19).
