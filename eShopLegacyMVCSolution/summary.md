# eShopLegacyMVC solution: .NET Framework → net10.0 migration

## Result

`dotnet build` succeeds with **0 errors and 0 warnings** for each upgraded project and for `eShopLegacyMVC.sln`:

| Project | Before | After |
| --- | --- | --- |
| `eShopLegacy.Utilities` | .NET Framework 4.6.1 class library | SDK-style, `net10.0;netstandard2.0` |
| `src/eShopLegacyMVC` | ASP.NET MVC 5 + Web API 2 + EF6 + Autofac.Mvc5/WebApi2 on .NET Framework 4.7.2 | ASP.NET Core MVC on `net10.0`, EF Core 10, Autofac via `Autofac.Extensions.DependencyInjection` |
| `eShopPorted` | ASP.NET Core 2.2 on `net461` | ASP.NET Core on `net10.0`, EF Core 10 |

`dotnet list package --vulnerable --include-transitive` reports no vulnerable packages. The solution has no test projects, so no unit tests could be run.

## What the old code did (from CodeKB) and what changed

### eShopLegacy.Utilities
- `Serializing.SerializeBinary` / `DeserializeBinary` used `BinaryFormatter`. Both `FilesController` classes call it to return the brand list from `GET api/files`.
- BinaryFormatter was removed from the runtime in .NET 9+ and always throws there. The `netstandard2.0` build keeps BinaryFormatter (`#if NETSTANDARD2_0`) for .NET Framework consumers. The `net10.0` build writes UTF-8 JSON with `System.Text.Json`. `DeserializeBinary` returns a `JsonElement` on net10.0.
- The project is now multi-targeted to `net10.0;netstandard2.0`. The working tree had it as `netstandard2.0` only, even though the instructions said multi-targeting was already applied. The unused `Microsoft.CSharp` and `System.Data.DataSetExtensions` packages were removed. `GenerateAssemblyInfo=false` keeps the existing `AssemblyInfo.cs`.

### src/eShopLegacyMVC
- **Project file**: rewritten as SDK-style `Microsoft.NET.Sdk.Web`. Removed `packages.config` and every System.Web, MVC5, WebApi2, EF6, ApplicationInsights, WebGrease/Antlr, CodeDom and binding-redirect dependency. New packages: Autofac 9.3.4, Autofac.Extensions.DependencyInjection 11.0.2, log4net 3.6.0, Microsoft.EntityFrameworkCore.SqlServer 10.0.15.
- **Global.asax / App_Start → `Program.cs`**:
  - `Application_Start`: Autofac container plus `ApplicationModule(UseMockData)`, MVC and attribute routes, and the conventional `{controller=Catalog}/{action=Index}/{id?}` route.
  - Database initializer: runs once at startup (scoped) when `UseMockData` is false.
  - `Application_BeginRequest`: middleware that sets the log4net `activityid` and `requestinfo` properties and writes the debug log line. `ActivityIdHelper` and `WebRequestInfo` moved to `RequestLogging.cs`. `WebRequestInfo` now captures the URL and User-Agent from `HttpRequest` instead of reading `HttpContext.Current`.
  - `Session_Start`: `AddSession` plus middleware that stores `MachineName` and `SessionStartTime` the first time a session is seen. The layout reads them with `Context.Session.GetString`.
  - `HandleErrorAttribute`: `UseExceptionHandler("/Error")` outside Development, served by a new `ErrorController`. Development uses the developer exception page.
  - `<globalization culture="en-US">`: `UseRequestLocalization` with en-US as the only culture, so currency and date formatting stay the same.
  - `BundleConfig`: plain `<link>`/`<script>` tags pointing at the same files the bundles contained.
- **Web.config → `appsettings.json`**: holds the `CatalogDBContext` connection string, `UseMockData` and `UseCustomizationData`. `Properties/launchSettings.json` keeps the old IIS Express port 52429. All `Web*.config` files, `Views/Web.config` and `ApplicationInsights.config` were deleted.
- **EF6 → EF Core 10**:
  - `CatalogDBContext` takes `DbContextOptions` and is registered with `AddDbContext`. The Autofac registration for it was removed.
  - The fluent mapping uses `EntityTypeBuilder`. It reproduces the EF6 schema: `decimal(18,2)` price, required FKs, `Catalog.Id` not generated by the database, and IDENTITY keys on `CatalogType`/`CatalogBrand`. As in EF6, the client-supplied Id values for those two tables are ignored on insert.
  - `CatalogItemHiLoGenerator` and the initializer use `SqlQueryRaw<long>(... AS [Value]).AsEnumerable().Single()`. Without `AsEnumerable()`, EF Core would wrap the query in a subquery, and SQL Server does not allow `NEXT VALUE FOR` there.
  - `CatalogDBInitializer`: `CreateDatabaseIfNotExists` is replaced by `InitializeDatabase()`, which calls `EnsureCreated()` and seeds only when the database was just created. `ConfigurationManager` became `IConfiguration` and `HostingEnvironment` became `IWebHostEnvironment`. Script paths now use `Path.Combine` so they work on Linux.
- **Controllers**:
  - MVC: `HttpStatusCodeResult`/`HttpNotFound` became `BadRequest()`/`NotFound()`, `[Bind(Include=...)]` became `[Bind(...)]`, and `Request.Url.Scheme` became `Request.Scheme`. `PicController` uses `IWebHostEnvironment.WebRootPath` instead of `Server.MapPath`.
  - Web API: `BrandsController` and `FilesController` now inherit `ControllerBase` with `[ApiController]` and explicit `api/[controller]` routes. The routes and HTTP verbs are unchanged.
  - JSON uses PascalCase names (`PropertyNamingPolicy = null`), the same as Web API 2 / MVC 5.
- **Static files**: `Content`, `Scripts`, `fonts`, `Images`, `Pics` and `favicon.ico` moved to `wwwroot` with `git mv`. Paths with the wrong case (`~/images` → `~/Images`, `Site.css`) were fixed because Linux file systems are case-sensitive.
- **Views**: added `_ViewImports.cshtml` (tag helpers and namespaces), replaced `Html.Partial` with `await Html.PartialAsync`, and replaced the session footer code.
- **log4net**: kept as the interim option described in KB 12 and upgraded from 2.0.10 to 3.6.0 (non-vulnerable). The `XmlConfigurator` attribute now points at `log4Net.xml`, matching the file name's case. The file is copied to the output folder, and the log path uses `/`.

### eShopPorted
- Removed packages that only work on .NET Framework or are unused: `Autofac.Mvc5`, `WebGrease`, `Antlr4`, `Microsoft.CSharp`, and the 2.2 `Microsoft.AspNetCore*` packages. Upgraded Autofac, Autofac.Extensions.DependencyInjection, log4net and EF Core (10.0.15). `EF Core Design` is now `PrivateAssets=all`.
- `Program`/`Startup` moved to the generic host with `AutofacServiceProviderFactory`. `ConfigureServices` returning `IServiceProvider` is no longer supported, so the module registration moved to `ConfigureContainer`. Routing changed from `UseMvc` to `UseRouting`/`UseEndpoints`, and `IHostingEnvironment` became `IWebHostEnvironment`.
- `PicController` still used `System.Web.Mvc`. It is now ported to ASP.NET Core and reads pictures from `wwwroot/Pics`.
- Added `Views/_ViewImports.cshtml` so the tag helpers resolve `~/` URLs. Fixed the image path case and the `Html.Partial` analyzer warning. Deleted `Views/Web.config` and `app.config`; the Web SDK already enables server GC.

## Behavioral changes to be aware of
- `GET api/files` now returns a JSON body (`application/json`). Before, it returned a BinaryFormatter payload with no content type, and BinaryFormatter cannot run on .NET 10. Any client that deserialized the binary payload must switch to JSON.
- `GET /api` (`CatalogController2`) now returns `{"Message":"Hello World!"}`. MVC 5's `Json()` blocked GET requests by default (`JsonRequestBehavior.DenyGet`), so the old endpoint returned an error.
- The database is created and seeded at application startup instead of on the first query.
- The development connection string adds `TrustServerCertificate=True`. Microsoft.Data.SqlClient encrypts connections by default, and LocalDB's certificate is not trusted.
- The footer session text is now HTML-encoded. Before, it was written with `HtmlString`.

## Next steps
- **Application Insights**: the MVC 5 Application Insights modules were removed, and no instrumentation key was configured. If telemetry is needed, add `Microsoft.ApplicationInsights.AspNetCore` or OpenTelemetry with a connection string from configuration or a secret store.
- **Logging**: log4net is kept as an interim choice. KB 12 recommends moving to `Microsoft.Extensions.Logging` (for example Serilog with a file sink) in a later cycle. The `%property{activity}` token in `log4Net.xml` does not match the `activityid` property the code sets. This bug existed before the migration and was left unchanged.
- **Autofac**: kept to preserve the `ApplicationModule` pattern. It could be replaced by built-in DI later.
- **PicController** (both apps): `PictureFileName` is combined into a file path without validation. This existed before the migration. Consider rejecting path separators or `..`.
- **eShopPorted**: `UseExceptionHandler("/Home/Error")` points to a `HomeController` that does not exist (this existed before). The EF Core 2.2 migration and model snapshot compile, but they should be regenerated with EF Core 10 tooling before running `Migrate()`, because EF 9+ throws on pending model changes. Its `FilesController` now returns JSON for the reason described above.
- **Seed SQL scripts** contain a hard-coded `USE [Microsoft.eShopOnContainers.Services.CatalogDb]`, which existed before. If the database name in the connection string changes, the sequences will be created in the wrong database.
- **Solution file**: the project-type GUID for `eShopLegacyMVC` in the `.sln` is still the legacy C# GUID. The build is unaffected.
- **Tests**: the solution has no test projects. Consider adding tests for `CatalogService`/`CatalogController` before more refactoring.
- Runtime verification against a real SQL Server or LocalDB instance was not possible in this cycle, because only build verification is allowed.
